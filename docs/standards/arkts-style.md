# ArkTS 编码标准

## 目录与依赖

- 页面只负责生命周期和组合 feature；业务规则放在 `domain` 或 feature 用例。
- 组件按单一职责拆分；不得把网络、文件、历史记录和 UI 状态写进同一个大组件。
- 使用明确的接口和联合类型，禁止 `any`、无约束的 `Record<string, Object>` 和隐式字符串协议。
- 所有异步系统调用都返回可判断的结果，错误不得被空 `catch` 吞掉。

## 状态与持久化

- `AppStorage`、`@State`、`@Observed` 只保存短生命周期 UI 状态。
- 文档、BYOK、用户设置等跨重启数据必须经 `platform` 持久化 port，并有读回测试。
- 状态更新必须经过单一 store/用例入口；组件不能直接改共享文档对象。

## 质量

- 不使用 `*.ets.bak`、复制组件或“临时兼容”分支进入正式目录。
- 新增对外方法必须说明输入约束、错误结果和测试位置。
- 弃用 API 必须在同一变更中替换并跑 ArkTS 编译；警告不能被当作通过证据。
- 注释解释约束和原因，不重复代码表面行为；正式新增文档和错误文案使用简体中文。
