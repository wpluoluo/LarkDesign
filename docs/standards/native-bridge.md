# Native Bridge 标准

## 接口边界

- NAPI 只暴露稳定 DTO、整数句柄和明确的错误结果，不暴露 `SkCanvas`、`SkImage` 等第三方类型。
- ArkTS 侧通过 `entry/src/main/ets/types/liblark_engine.d.ts` 固定模块签名；当前 DevEco 6.0.2 仍会提示本地 `.so` 的模块验证建议，该提示不阻断编译，发布前需随 SDK 升级重新确认。
- 每个函数先校验参数数量、类型、句柄有效性和整数溢出，再调用 C ABI。
- 句柄创建、使用、销毁必须成对；跨线程和生命周期约束写入接口文档。
- ArkTS 不能根据错误消息猜测状态；错误码必须是稳定的顶层字段。

## 渲染与导出

- `scene_graph` 必须解析受版本约束的场景 DTO；解析失败或不支持的节点必须返回失败，不能返回固定成功。
- Skia 是唯一画布渲染后端。ArkUI 画布占位只能用于开发调试，不能作为正式渲染实现。
- 导出函数必须返回真实字节或明确写入文件，并覆盖 PNG/JPEG/WebP 等已声明格式；未实现格式不得在 UI 报告成功。
- 所有导出路径必须有最小输入、空场景、透明度和错误路径测试。

## 构建与依赖

- CMake 必须在目标 ABI 上编译，并记录 Skia/lcms2/字体库版本和许可证。
- 第三方目录为空时构建应明确失败，不得链接到本机偶然路径。
- NAPI 变更必须同时运行 C++ 编译、ArkTS 调用契约测试和内存边界检查。
